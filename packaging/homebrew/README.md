# Homebrew tap (getkono/homebrew-tap)

kmux is distributed through the existing `getkono/homebrew-tap` repository as two
formulae:

- **Cask `kmux`** — the signed, notarized macOS desktop app (GUI). Installs
  `kmux.app` to `/Applications` and links the bundled `kmux` CLI onto `PATH`.

      brew install --cask getkono/tap/kmux

- **Formula `kmux`** — the CLI + daemon only (headless), for macOS users who
  don't want the GUI, servers, and Linuxbrew. Installs the prebuilt binaries from
  the release tarball.

      brew install getkono/tap/kmux

The Linux GUI is **not** shipped via Homebrew (the GTK stack is awkward under
Linuxbrew) — use the native `.deb`/`.rpm`/AUR/flatpak packages there instead.

## How the files are maintained

Both files are generated by [`render.sh`](render.sh) from a release's published
checksums — it is the single source of truth, so do not hand-edit
`Formula/kmux.rb` / `Casks/kmux.rb` in the tap. On every release the
`update-tap` job in `.github/workflows/release.yml`:

1. reads the `*.sha256` sidecars from the just-published GitHub Release,
2. runs `render.sh` to regenerate `Formula/kmux.rb` and `Casks/kmux.rb`,
3. commits and pushes them to `getkono/homebrew-tap`.

This needs a `HOMEBREW_TAP_TOKEN` secret (a PAT / fine-grained token with
`contents: write` on `getkono/homebrew-tap`) on the `getkono/kmux` repo. The cask
is only (re)generated once a signed release exists (it needs the `.dmg`
checksums); the formula is regenerated every release.

## Seeding the tap by hand

To populate the tap for the first time (or render locally), run from a kmux
checkout with the target release's checksums in the environment:

```sh
VERSION=0.2.0 \
SHA_TAR_ARM_MAC=… SHA_TAR_X86_MAC=… SHA_TAR_ARM_LIN=… SHA_TAR_X86_LIN=… \
SHA_DMG_ARM=… SHA_DMG_X86=… \
  packaging/homebrew/render.sh /path/to/homebrew-tap
```

Then commit the generated `Formula/kmux.rb` + `Casks/kmux.rb` in the tap repo.
